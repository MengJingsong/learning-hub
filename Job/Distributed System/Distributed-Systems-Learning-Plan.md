## 2. 范围与学习方式

- **按主题组织**：下文的模块是主题，不是书的章节。每个模块同时列出两本书的对应部分；DS 给出概念与算法，DDIA 给出数据系统中的实现与取舍。两本书说法不同时，分别说明，不强行合并。
- **中文为主，中英对照**：按第 3 节的双语规则讲解。
- **每次只讲一个具体知识点**：直觉 → 精确定义 → 前提与机制 → 分步例子 → 边界与失败情形 → 工程取舍与面试表达。讲透细节，不做面面俱到的浅层概览。
- **专注讲解与答疑**：不主动发起测验、理解检查、热身提问或课后练习。只有学习者明确要求时才测试或练习；测试时一次一题，先由学习者作答再反馈。
- **由学习者决定节奏**：讲完一个知识点后停在自然的位置，等学习者提问或明确要求进入下一个。不按时间或整模块赶进度。
- **选题前先读记录**：读取本计划、[Session Log](session-log.md) 和 [Mastery](mastery.md)。“从头开始”从模块 1 的第一个知识点讲起；“继续”接着 Session Log 的 checkpoint。
- **讲解与评估分开记录**：听过讲解不等于掌握；只有评估证据才能更新 Mastery。
- **区分来源**：讲解时区分教材观点、learning-hub 自拟案例和需要核对的版本相关细节。

### 2.1 贯穿案例：Hadoop 与 Cassandra

每个模块都用 Hadoop 和 Apache Cassandra 做对照案例。两者在多数主题上做了相反的设计选择，适合对比：Hadoop（HDFS、YARN、MapReduce）是有中心的主从结构，Cassandra 是无主的对等结构。

- DS 全书没有提到 Hadoop 和 Cassandra；DDIA 多次讨论两者（尤其 Ch.3、Ch.5、Ch.6、Ch.10）。因此在 DS 主题下的这两个案例属于 learning-hub 自拟案例，讲解时要标明。
- 案例只讲与当前知识点直接相关的机制，不展开成产品教程。
- 版本相关的细节（配置项、默认值、某版本是否支持某功能）以官方文档为准，核对后再讲；默认参照 Hadoop 3.x 和 Cassandra 5.0.x。不确定时明说。
- 案例可以联系学习者的研究方向（Cassandra 内部机制、throttling 与资源限制），但只在与知识点相关时提及。

## 3. 双语讲解规则

对以下六类内容使用**中英对照**；普通的过渡和叙述用中文。

| 类型 | 做法 |
|---|---|
| **概念点**（concept） | 英文术语 + 中文名；一句英文定义 + 中文解释。缩写首次出现时给出英文全称和中文，如“远程过程调用（RPC, remote procedure call）”。 |
| **要点**（main point） | 先用一句英文陈述，再用中文展开。 |
| **关键点**（key point） | 决定理解成败的结论或条件：英文陈述 + 中文解释，并说明它为什么关键。 |
| **难点**（difficult point） | 英文的精确表述 + 中文拆解；指出容易混淆的相近概念，并对比两者的英文术语。 |
| **长难句**（long sentence） | 展示教材原句 → 主干 → 从句与修饰关系 → 关键搭配 → 自然的中文译文 → 在技术语境中的含义。 |
| **省略句**（elliptical sentence） | 展示教材原句 → 补全被省略的成分 → 中文译文 → 说明为什么可以省略。 |

补充规则：

- 中英对照要融入讲解的相应位置，不集中放在课后。不需要单独的课后词汇表。
- 优先使用教材自己的术语和表达；解释有用的构词、搭配和近义术语的区别。不机械翻译普通的功能词和过渡句。
- **不常用词中英对照**：讲解中遇到较生僻的词、搭配和技术用语，就地给出英文与简明中文释义；必要时加简短英文解释。保持融入正文，不另设课后生词表。
- 原文只引用需要拆解的句子，保持简短；其余内容用自己的话讲。
- 在案例中复用本课的英文术语，强化对应关系。
- 学习者用英文回答或提问时，给出有选择的纠正，保留其原意。
- **English inbox**：每次讲解结束时，先对 `/english/english-study/inbox.md` 查重，再把本课最值得长期复习的词、搭配和句型按既有格式加入。条目保持轻量。

## 6. 模块

每个模块给出：逐课顺序、教材对应、Hadoop 与 Cassandra 案例、要能解释的问题。标“选学”的部分不在主线上。

### 模块 1：基础与设计目标

- 概念 ID：`ds.intro`
- **逐课顺序**：分布式与去中心化（distributed vs. decentralized）→ 八个研究视角 → 设计目标：资源共享、分布透明性、开放性、可依赖性、安全、可扩展性 → 系统分类 → 常见错误假设（pitfalls）→ DDIA 的可靠性、可扩展性、可维护性，以及负载与性能的描述方法（百分位数）。
- **教材对应**：DS §1.1–§1.5；DDIA Ch.1。
- **案例**：HDFS 的 NameNode 是逻辑上的中心，对照 DS Note 1.1“集中式方案并不一定差”；Cassandra 的各项透明性做到了什么程度，哪些有意暴露给用户（如一致性级别）。
- **要能解释**：sufficiently spread 和 necessarily spread 的区别；availability 和 reliability 为什么不同；为什么完全的分布透明性做不到；尾延迟（tail latency）为什么比平均值重要。

### 案例导读（模块 1 之后）

- 概念 ID：`ds.case.hadoop-overview`、`ds.case.cassandra-overview`
- 各用一次课建立整体图景，后续模块再逐点深入。Hadoop：HDFS（NameNode、DataNode、块）、YARN（ResourceManager、NodeManager）、MapReduce 的角色分工。Cassandra：对等节点、环与分区、可调一致性、写路径与读路径的大致流程。
- **教材对应**：DDIA Ch.10「MapReduce and Distributed Filesystems」开头部分、Ch.5「Leaderless Replication」开头部分；其余内容以官方文档为准。

### 模块 2：架构

- 概念 ID：`ds.arch`
- **逐课顺序**：分层架构 → 面向服务与发布-订阅 → 中间件的组织 → 客户端-服务器与多层架构 → 结构化与非结构化 P2P → 云与边缘的混合架构。
- **教材对应**：DS Ch.2（§2.5.3 区块链架构选学）。
- **案例**：HDFS 和 YARN 的主从架构与 Cassandra 的对等架构对比：元数据放在哪里、单点在哪里、扩容时谁需要知道变化。
- **要能解释**：逻辑上集中和物理上集中的区别；主从与对等各自把复杂度放在了哪里。

### 模块 3：进程、线程与虚拟化

- 概念 ID：`ds.process`
- **逐课顺序**：线程与多线程服务器 → 虚拟机与容器 → 服务器设计问题（并发模型、有状态与无状态）→ 服务器集群与请求分发 → 代码迁移（选学）。
- **教材对应**：DS Ch.3（§3.3 客户端部分选学）。
- **案例**：YARN 用容器隔离和分配资源；Cassandra 节点内部的线程池、排队与背压，联系资源限制与 throttling。
- **要能解释**：有状态服务器在故障恢复时多出哪些问题；线程池大小和队列长度如何影响延迟与过载行为。

### 模块 4：通信与数据编码

- 概念 ID：`ds.comm`
- **逐课顺序**：分层协议与通信类型（瞬时与持久、同步与异步）→ RPC 的基本操作与参数传递 → 面向消息的通信与消息队列 → 多播与 gossip 传播 → 编码格式与模式演化（schema evolution）→ 数据流的三种方式。
- **教材对应**：DS Ch.4；DDIA Ch.4。
- **案例**：Hadoop RPC 与序列化格式，Avro 最初是 Hadoop 的子项目（DDIA Ch.4）；Cassandra 用 gossip 传播节点状态与成员信息。
- **要能解释**：RPC 为什么不能完全等同于本地调用；向前兼容与向后兼容的区别；gossip 的收敛速度和代价。

### 模块 5：时钟、顺序与协调

- 概念 ID：`ds.time`
- **逐课顺序**：物理时钟与时钟同步 → 单调时钟与日历时钟 → Lamport 逻辑时钟 → 向量时钟与因果关系 → 互斥 → 选举算法。
- **教材对应**：DS §5.1–§5.4（§5.5–§5.7 选学）；DDIA Ch.8「Unreliable Clocks」、Ch.9「Ordering Guarantees」。
- **案例**：Cassandra 用时间戳做“最后写入者胜”（LWW, last write wins），时钟偏差会造成什么后果；HDFS NameNode 高可用依赖 ZooKeeper 做主备选举（对照 DS §5.4.3）。
- **要能解释**：为什么不能用物理时间戳给跨节点事件排序；Lamport 时钟和向量时钟各能推出什么、推不出什么。

### 模块 6：命名与分区

- 概念 ID：`ds.partition`
- **逐课顺序**：名字、标识符与地址 → 分布式哈希表（DHT）→ 结构化命名与名字解析 → 按键范围分区与按哈希分区 → 热点与数据倾斜 → 二级索引 → 再平衡 → 请求路由。
- **教材对应**：DS §6.1–§6.3（§6.4–§6.5 选学）；DDIA Ch.6。
- **案例**：Cassandra 的一致性哈希、虚拟节点（vnodes）和 partition key 的选择；HDFS 的命名空间由 NameNode 集中管理，文件切成块后分布到 DataNode。
- **要能解释**：哈希分区为什么丢失了范围查询能力；节点增减时为什么不能用 hash mod N；热点键如何处理。

### 模块 7：复制

- 概念 ID：`ds.replication`
- **逐课顺序**：复制的理由与代价 → 主从复制、同步与异步 → 复制日志的实现 → 复制延迟带来的问题 → 多主复制与写冲突 → 无主复制与 quorum → sloppy quorum 与 hinted handoff → 并发写的检测 → 副本放置与内容分发。
- **教材对应**：DS §7.1、§7.4、§7.5；DDIA Ch.5。
- **案例**：HDFS 的块复制、写入管线与机架感知放置；Cassandra 的复制因子、一致性级别、hinted handoff、read repair 与反熵修复。
- **要能解释**：W + R > N 保证了什么、不保证什么；异步复制下故障切换会丢什么；LWW 为什么会丢数据。

### 模块 8：一致性模型

- 概念 ID：`ds.consistency`
- **逐课顺序**：以数据为中心的模型（顺序一致性、因果一致性、最终一致性）→ 以客户端为中心的模型（单调读、单调写、读己之写、写后读）→ 线性一致性（linearizability）→ 线性一致性的代价与 CAP → 一致性协议的实现。
- **教材对应**：DS §7.2、§7.3、§7.5、§8.2.7；DDIA Ch.9「Consistency Guarantees」「Linearizability」，Ch.5「Problems with Replication Lag」。
- **案例**：Cassandra 的可调一致性在不同级别下分别对应哪种保证；HDFS 把元数据一致性集中在 NameNode 上，并限制单个文件只有一个写入者。
- **要能解释**：线性一致性与可串行化（serializability）的区别；CAP 的准确含义和常见误读；最终一致性没有承诺什么。
- 两本书对一致性模型的分类方式不同，讲解时分别说明并建立对应关系。

### 模块 9：存储引擎

- 概念 ID：`ds.storage`
- **逐课顺序**：日志结构与哈希索引 → SSTable 与 LSM 树 → 压实（compaction）→ B 树 → 两者的比较 → 事务处理与分析 → 列式存储。
- **教材对应**：DDIA Ch.3（Ch.2 数据模型选学）。DS 没有对应章节。
- **案例**：Cassandra 的 commit log、memtable、SSTable 与压实策略，压实对读写延迟和磁盘 I/O 的影响；HDFS 面向大文件的追加写与顺序读，以及其上的列式文件格式。
- **要能解释**：LSM 树为什么写入快；写放大（write amplification）从哪里来；压实跟不上写入时会发生什么。

### 模块 10：事务

- 概念 ID：`ds.txn`
- **逐课顺序**：ACID 各自的准确含义 → 单对象与多对象操作 → 读已提交 → 快照隔离 → 丢失更新 → 写偏斜与幻读 → 可串行化的三种实现（串行执行、两阶段锁、可串行化快照隔离）→ 嵌套事务与事务处理监视器。
- **教材对应**：DDIA Ch.7；DS §1.3.2。
- **案例**：Cassandra 的轻量级事务（LWT, lightweight transaction）基于 Paxos，只提供有限的事务能力；Hadoop 批处理通过整体重算和原子输出来避免事务。
- **要能解释**：ACID 中的 C 和 CAP 中的 C 为什么不是一回事；快照隔离挡不住哪种异常；两阶段锁（2PL）和两阶段提交（2PC）的区别。

### 模块 11：故障模型与容错

- 概念 ID：`ds.fault`
- **逐课顺序**：fault、error、failure 与故障模型 → 部分失效 → 不可靠的网络、超时与无界延迟 → 进程暂停 → 故障检测 → 用冗余掩盖故障 → 进程组 → 故障下的 RPC 语义 → 可靠的组通信 → 检查点与恢复。
- **教材对应**：DS §8.1、§8.2.1–§8.2.2、§8.2.8、§8.3、§8.4、§8.6；DDIA Ch.8。
- **案例**：HDFS 用心跳和块报告检测 DataNode 故障并重新复制；Cassandra 的 phi accrual 故障检测器，以及长时间 GC 暂停造成的误判。
- **要能解释**：为什么无法区分慢节点和死节点；at-least-once 与 at-most-once 的区别；超时设得太短或太长各有什么后果。

### 模块 12：共识与分布式提交

- 概念 ID：`ds.consensus`
- **逐课顺序**：崩溃故障下的共识 → FLP 不可能性 → Paxos → Raft 的领导者选举 → 全序广播 → 两阶段提交及其阻塞问题 → 成员与协调服务（ZooKeeper）→ 拜占庭故障（选学）。
- **教材对应**：DS §8.2.3–§8.2.7、§8.5、§5.4.3–§5.4.4；DDIA Ch.9「Distributed Transactions and Consensus」。
- **案例**：HDFS NameNode 高可用用基于多数派的日志（JournalNode）加 ZooKeeper 防止脑裂；Cassandra 的 LWT 在单个分区上运行 Paxos。
- **要能解释**：2PC 为什么不是共识算法；多数派为什么能防止脑裂；fencing token 解决什么问题。

### 模块 13：批处理与流处理

- 概念 ID：`ds.dataflow`
- **逐课顺序**：Unix 管道的设计思想 → MapReduce 的作业执行 → reduce 端与 map 端的连接 → 批处理输出与容错 → MapReduce 之后的数据流引擎 →（选学）消息系统与分区日志、流处理、数据系统的未来。
- **教材对应**：DDIA Ch.10 为主线，因为它直接讲 Hadoop；Ch.11、Ch.12 选学。DS 没有对应章节。
- **案例**：MapReduce 在 HDFS 和 YARN 上的执行过程；Cassandra 作为批处理的数据源或输出目标时的取舍。
- **要能解释**：把计算移到数据所在处为什么有效；MapReduce 靠什么实现容错；批处理和分布式数据库的设计目标有何不同。

### 模块 14：安全（选学）

- 概念 ID：`ds.security`
- **逐课顺序**：威胁、策略与机制 → 对称与非对称加密、哈希 → 认证协议 → 信任 → 授权与委托 → 监控。
- **教材对应**：DS Ch.9，以及 §1.2.5 的预备内容。
- **案例**：Hadoop 使用 Kerberos 做认证；Cassandra 的认证、授权与节点间加密。

## 7. 建议学习路线

| 阶段 | 模块顺序 | 阶段产出 |
|---|---|---|
| A：建立整体图景 | 1 → 案例导读 → 2 → 3 | 能说明两种系统的整体结构和各自的设计目标 |
| B：通信、时间与故障 | 4 → 5 → 11 | 能解释消息、时钟和故障三方面的不确定性从哪里来 |
| C：数据的存放与副本 | 9 → 6 → 7 → 8 | 能沿一次写入和一次读取，讲清分区、复制与一致性保证 |
| D：正确性 | 10 → 12 | 能区分隔离级别、原子提交与共识 |
| E：数据流与安全 | 13 → 14（选学） | 能解释 MapReduce 的执行与容错 |

路线可以按学习者的问题、研究需要或先修情况调整。跳到后面的模块时，只补当前知识点需要的先修。
