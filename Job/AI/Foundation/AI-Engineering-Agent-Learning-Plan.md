## 1. 范围与学习方式

本计划属于 AI 概念与工程学习，与 [AI infrastructure 索引](../Infrastructure/Resources.md) 互补。后者侧重 GPU、训练、推理服务与集群；本计划侧重模型之上的应用逻辑、工具、数据与运行时。二者在延迟、成本、服务可靠性和可观测性方面有交集。

- 中文为主，术语保留 English，并在首次出现时配中文释义。参考 Distributed System 学习计划：重要知识点、关键术语与必要的原文长难句采用中英双语讲解；长句拆解主干、从句/修饰关系与关键表达，再给自然中文译文和技术语境解释。
- 每次只讲一个具体知识点：直觉 → 精确定义 → 前提与机制 → 分步例子 → 边界/失败情形 → 工程取舍与面试表达。重点讲透细节，不用面面俱到的浅层概览。
- 专注讲解与答疑，不主动发起测验、理解检查、热身提问或课后练习；只有学习者明确要求时才测试或练习。一次一题，先由学习者作答再反馈。
- 选题前读取 [AI mastery](../mastery.md) 与 [session log](../session-log.md)，依据先修与实际证据调整深度，不因记录为空默认零基础。
- 讲解与评估分开记录；只有有效评估证据才能支持掌握程度更新。
- 当前没有足够的评估证据判断起点。续学从学习记录中的 `ae.tool-calling.request-vs-execution` 开始；不熟悉 API、JSON 或异常处理时，再按需补模块 1。
- 不设置硬性周数。以能够解释机制、独立完成最小练习和处理失败情形作为推进依据。

### 1.1 单知识点复习与推进规则

用户偏好（2026-10-28）：每次只复习一个具体知识点，充分弄懂后再进入下一个；不按时间或整模块赶进度。

1. **确定一个小知识点**：先读本计划与 AI 学习记录，明确本次主题和边界。下面九个核心模块是主线目录，不是一次课的单位；达到先修后，可选择进阶专题。例如“工具调用”应进一步拆成“模型提出调用请求与程序实际执行的区别”“参数 schema”“结果回传”等，逐个复习。
2. **详细讲解并答疑**：从直觉推进到精确定义、假设、机制、逐步例子、边界和取舍；解释术语间易混淆点、常见误区、故障场景及其因果链。必要时只补当前点的先修，然后回到原主题。
3. **面试重点讲清楚**：对高频基础和系统设计主题明确说明面试常考定义、适用条件、设计权衡、失败处理、性能/成本影响及容易答错之处；给出组织答案的思路或示例表达，不把面试问答变成未经请求的测验。
4. **练习与测试按需进行**：不主动布置练习或检查理解；学习者要求测试/练习时，再按一次一题执行，并根据真实表现反馈。听过解释或表示理解不等于评估通过。
6. **保存后可续学**：有意义的讲解或答疑后，在 session-log 中简要记录具体知识点 ID、当前阶段、剩余疑问和下一步；评估后再据证据更新 mastery，区分独立作答与提示后完成。跨会话继续时先读记录，优先接着当前未完成知识点。保存成功后才报告已记录。

## 2. 九个核心模块与进阶专题

### 模块 1：模型调用与结构化输出

- 概念 ID：`ae.model-io`
- 先修：Python 基础、HTTP/API、JSON；有短板时按需补。
- 内容：消息与角色、指令和外部数据的区分、上下文窗口、token、流式响应、结构化输出、schema 校验、超时与速率限制。
- 要能解释：模型输出为何需要程序校验？格式合法与语义正确有什么区别？流式输出如何影响前端与错误处理？
- 最小练习：给定一段教材内容，输出包含 topic_id、summary、prerequisites、source_refs 的 JSON；验证必填字段和类型，显式处理拒绝、截断和校验失败。
- 验收证据：合法响应可解析；缺字段或错误类型不会静默进入后续流程；不把符合 schema 当成内容正确。
- 资料：实际选用模型服务商的当前官方 API 文档；开始编码时核对具体模型的结构化输出与流式支持，不假设不同服务商完全兼容。

### 模块 2：工具调用（Tool calling）

- 概念 ID：`ae.tool-calling`
- 先修：ae.model-io。
- 内容：工具名称和描述、参数 schema、工具选择、调用结果回传、输入校验、超时、失败分类、最小权限。
- 关键机制：模型提出工具调用请求；宿主程序验证并执行；执行结果作为后续模型调用的输入。模型生成调用请求不等于操作已完成。
- 要能解释：工具与普通文本回答有何区别？参数不合法、工具不可用、返回空结果时怎样处理？
- 最小练习：提供 read_material 与 search_notes 两个只读工具，限定可读目录；让模型选择工具，并用模拟错误验证执行器。
- 验收证据：能区分请求、实际执行和确认成功；无效参数被拒绝；工具失败不会被报告成成功。
- 资料：S1 的工具设计部分；S4 用于后续学习标准化工具连接。

### 模块 3：Agent 执行循环

- 概念 ID：`ae.agent-loop`
- 先修：ae.tool-calling。
- 内容：行动选择、执行、观察、状态更新、再次决策；完成条件、步数上限、时间与费用预算、重复行为检测。
- 要能解释：单次 LLM 调用为何不必然构成 Agent？模型负责决策、执行器负责操作，二者如何分工？如何避免无限循环？
- 最小练习：实现一个能搜索资料、读取内容并回答问题的单 Agent；先使用简单循环和明确状态，不要求引入框架。
- 验收证据：找到足够证据能停止；资料不足能说明限制；遇到重复搜索或超出预算会终止；保留实际行动记录。
- 资料：S1、S7。

### 模块 4：Workflow 编排与任务拆解

- 概念 ID：`ae.orchestration`
- 先修：ae.agent-loop、基本控制流。
- 内容：prompt chaining、routing、并行、条件分支、状态机、依赖关系、计划与执行分离、重新规划；单 Agent 与多 Agent 的取舍。
- 概念边界：Workflow 可以包含分支、循环和重试，并非只能线性执行。区别在于控制路径由程序预先定义，还是由模型在执行时动态组织。
- CoT、任务拆解与 ReAct：CoT 研究中间推理步骤；任务拆解产生子任务及依赖；ReAct 研究推理与外部行动交替。它们不等同，也不要求系统公开模型完整内部推理。
- 最小练习：对同一“查阅教材并生成复习说明”任务，比较固定工作流与受约束 Agent，记录成功率、调用次数、延迟与成本。
- 验收证据：能说明哪些步骤应该固定、哪里需要动态决策；能解释多 Agent 增加的协调成本；先验证单 Agent 是否足够。
- 资料：S1、S6、S7。

### 模块 5：上下文工程（Context engineering）

- 概念 ID：`ae.context`
- 先修：ae.model-io、ae.agent-loop。
- 内容：指令、历史消息、工具结果和外部资料的组织；按需加载、检索、摘要与压缩；信息新鲜度、上下文预算与来源。
- 要能解释：为何不能把所有资料都塞进 prompt？摘要可能丢失哪些约束？如何避免旧记录覆盖新事实？
- 最小练习：针对 learning-hub 的问题，只加载相关指令、教材片段与学习记录；比较全量加载和按需加载。
- 验收证据：关键用户约束保留；来源与版本可追踪；摘要不伪造事实；在减少输入量后检查答案质量。
- 资料：S2。

### 模块 6：RAG 与知识检索

- 概念 ID：`ae.rag`
- 先修：ae.model-io、ae.context；了解基本搜索概念。
- 内容：PDF/Markdown 解析、分块与元数据、关键词与向量检索、混合检索、重排、检索后生成、来源引用、索引更新。
- 概念边界：RAG 不等于微调，不要求一定使用向量数据库，也不要求一定采用 Agent。
- 要能解释：答案错误是没有检索到资料，还是模型没有正确利用资料？页码、章节和来源如何保留？
- 最小练习：从已有 DDIA 或 Distributed Systems 中选一章建立可追溯检索；先做关键词基线，再决定是否加入 embedding 和重排。
- 验收证据：回答附真实来源；无相关证据时说明不足；分别检查检索召回与答案依据；不编造页码。
- 资料：S3；仓库已有书籍见 [资料目录](README.md)。
- 专题：[RAG 知识点、待学清单与面试题](../rag.md)。

### 模块 7：状态与记忆管理

- 概念 ID：`ae.memory`
- 先修：ae.agent-loop、ae.context。
- 内容：任务状态、会话内记忆、跨会话长期记录；thread/session/user 标识、读写时机、更新冲突、数据新鲜度、隔离与删除。
- 要能解释：对话历史与掌握程度记录为何应分开？记忆写入如何验证？错误记录如何纠正？
- 最小练习：将“当前知识点与阶段”作为任务状态，将“学习偏好与评估证据”作为独立记录；暂用测试文件或数据库，不直接修改正式 mastery。
- 验收证据：不同用户或会话不串数据；仅听过讲解不会被写成掌握；更新有来源和时间；写入失败可见。
- 资料：S2、S5。

### 模块 8：持久化、失败恢复与人工介入

- 概念 ID：`ae.reliable-execution`
- 先修：ae.orchestration、ae.memory、基本存储与异常处理。
- 内容：checkpoint、持久化、暂停与恢复、超时、重试与退避、幂等键、重复副作用、人工审查；理解应用状态恢复不等于外部操作恰好执行一次。
- 要能解释：写记录成功但确认响应丢失后，能否直接重试？内存中的 checkpoint 能否跨进程重启保存？
- 最小练习：在模拟写入前后注入故障，重启并恢复；对同一测评事件使用稳定事件 ID 防止重复写入；模拟人工修改或拒绝操作。
- 验收证据：进程重启后可从持久状态恢复；重试不重复新增同一事件；失败与等待人工处理的状态明确。
- 资料：S5，并结合已有分布式系统教材学习一致性和故障语义。

### 模块 9：评估、可观测性与权限安全

- 概念 ID：`ae.evaluation-safety`
- 先修：最小 Agent 可运行；基础校验和权限控制从模块 1–2 即开始，不能留到最后才实施。
- 内容：回归测试集、任务成功判定、输出与实际环境状态校验、多次运行、执行轨迹、工具参数与结果日志、延迟与费用；最小权限、敏感数据、外部内容的 prompt injection、人工介入边界。
- 要能解释：回答“已保存”与文件真实保存为何要分别验证？如何识别失败来自检索、工具还是模型决策？为什么不能把外部文档中的指令当成用户授权？
- 最小练习：建立至少 12 个可重复案例，覆盖正常流程、资料缺失、无效参数、工具超时、重复写入和恶意外部指令；为每例定义预期行为。
- 验收证据：比较成功率、延迟、调用次数与成本；对不稳定任务做重复运行；失败可通过日志定位；日志避免记录密钥；越权请求被阻止。
- 资料：S8；协议与工具边界参照 S4。安全案例是本计划的工程练习建议，需结合实际服务的官方安全文档实现。

### 模块 10：上下文运行时与长程 Agent 上下文管理

- 概念 ID：`ae.context-runtime`
- 先修：模块 3 Agent loop、模块 5 上下文工程；按需回顾模块 6 RAG。
- 内容：上下文查看、手动压缩、自动压缩与清空/重置会话的行为差异；任务状态与对话上下文的区别；长程 coding agent 的上下文维护。
- 重点边界：依据官方文档说明产品可观察行为；区分已明确记录的行为和未公开的内部实现，不从命令名称臆测实现。
- 要能解释：压缩前哪些信息应保留？摘要丢失约束会造成什么问题？为什么恢复任务状态不等于恢复全部上下文？
- 面试重点：上下文窗口限制下如何设计长任务；何时压缩、检索或重新读取原始资料；如何防止摘要丢失关键约束和来源。
- 最小练习：为长时 coding task 设计上下文预算和压缩前后的关键信息清单。
- 验收证据：能区分上下文管理操作、会话状态与实现细节，并说明信息损失风险。
- 资料：S11，结合 S2。

### 模块 11：Prompt cache 与 KV cache

- 概念 ID：`ae.cache`
- 先修：模块 1 模型调用、模块 3 Agent loop、模块 5 上下文工程；理解 Transformer 推理基本过程。
- 内容：API/服务层 Prompt caching 与模型推理时 KV cache 的位置、缓存对象、生命周期、前缀匹配/复用条件、失效因素、可观测指标及费用和延迟影响。
- 核心区别：Prompt cache 通常复用服务端已处理的稳定提示前缀；KV cache 保存自回归生成过程中的注意力键和值。两者所在层次、对象、作用时机和可见指标不同，不可混称。
- 要能解释：为什么稳定前缀有利于命中？动态内容放置如何影响前缀复用？一次未命中可能由哪些边界、版本或时间条件造成？KV cache 如何减少重复计算，又受哪些内存限制？
- 面试重点：缓存正确性与失效、缓存隔离/数据边界、命中率与延迟/费用指标、内存容量和吞吐权衡；回答时说明缓存在哪一层、复用了什么、失效后正确性如何保证。
- 最小练习：固定系统提示和工具定义、改变请求后缀，记录 cached/uncached tokens、延迟与费用；解释冷启动、前缀差异和 TTL 等潜在影响。
- 验收证据：能准确区分两类缓存；依据 API usage 指标而非单看响应速度判断命中；说明至少一个系统代价。
- 资料：S10、S12。

### 模块 12：Mixture of Experts（MoE）与专家并行

- 概念 ID：`ae.inference.moe`
- 先修：模块 1、模块 3；理解 Transformer 前馈层和基本推理成本。
- 内容：专家网络、router/gating、token-to-expert 路由、top-k 激活、负载均衡、总参数与每 token 激活参数、专家并行通信。
- 要能解释：稀疏激活为何可能扩大模型容量但控制每 token 计算量？路由不均衡如何导致热点和尾延迟？为什么总参数少/激活参数少不能直接推出服务成本低？
- 面试重点：区分参数容量、每 token FLOPs、显存占用和跨设备通信；解释 all-to-all 路由成本、负载均衡与吞吐/延迟的权衡；避免把“稀疏”说成“没有通信成本”。
- 最小练习：画出 token 经 router 分派到专家并汇总输出的过程，标注跨设备通信及负载倾斜风险。
- 验收证据：能描述路由机制并区分总参数、激活参数、计算、显存与通信开销。
- 资料：S10、S13 DeepSeekMoE。

### 模块 13：Multi-head Latent Attention（MLA）与 KV 表示压缩

- 概念 ID：`ae.inference.mla`
- 先修：模块 1；掌握注意力与模块 11 的 KV cache 基础。
- 内容：标准多头注意力的 K/V 表示与缓存开销；latent 表示压缩、解压/投影路径、每 token KV cache 占用及吞吐、质量和实现复杂度取舍。
- 要能解释：MLA 如何改变需要缓存的表示？它对 KV cache 容量和推理服务有何潜在帮助？它与 prompt caching、对话摘要、RAG 有何区别？
- 面试重点：先讲缓存对象和张量/表示路径，再谈显存、带宽、并发容量；说明计算、质量、kernel 支持和硬件利用率等代价，避免把论文结果泛化为所有模型和硬件的保证。
- 最小练习：画出标准 MHA 的 K/V 缓存与 MLA latent 缓存的概念对照图，说明省下的存储与额外计算/实现要求。
- 验收证据：能区分模型层 KV 表示压缩与应用层上下文压缩，并给出有边界的系统取舍。
- 资料：S10、S13 DeepSeek-V2。

每次仍只学习一个子知识点。上述模块属于核心目录与主线课程，进度统一记入 AI Mastery 和 AI Session Log。

## 4. 综合项目：learning-hub 学习助手

目标：以已有仓库与教材为数据源，完成“选知识点 → 检索与讲解 → 答疑 → 用户要求后测试 → 根据证据记录”的学习过程。

建议实现顺序：

1. 只读版本：读取 router、相关 AI 指令和资料索引；检索教材；给出带来源的解释。
2. 选题版本：读取真实学习记录，依据先修、薄弱项和历史证据推荐一个知识点；证据不足时说明未知。
3. 状态版本：记录当前主题、讲解/答疑/测试阶段，支持中断后继续；正式测试仍由用户触发。
4. 测评版本：一次一题，记录独立作答、提示与错误；先写测试目录，验证规则后再接正式记录。
5. 完整版本：加入持久化、重试去重、权限控制与评估集，确认实际写入成功后才向用户报告完成。

最小实现可以使用 Python、模型 API、文件系统和 SQLite；先理解机制，再按需要引入 LangGraph。MCP 在需要标准化外部工具连接时学习，不作为最小版本的强制依赖。暂不要求自建模型推理服务、GPU 集群或多 Agent。

这是后续实践设计，本文件的创建不代表已实现上述系统，也不自动授权未来执行外部操作。
