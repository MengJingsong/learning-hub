# CS 常用指令速查

想学习概念，使用 CS；想模拟求职面试，使用 interview。本文件汇总既有模式和可复制的自然语言请求，不新增简短口令，也不自动启动学习。

## 1. 最常用的指令

| 我想做什么 | 直接发送 | 接下来会发生什么 |
|---|---|---|
| 进入计算机学习 | `CS模式` / `计算机模式` | 选择 CS 类别；继续告诉我主题或使用下面的完整请求 |
| 学习指定概念 | `CS模式，学习 GPU 内存层次` | 讲清直觉、定义、机制、例子和取舍 |
| 自动选择 AI infrastructure 知识点 | `CS模式，根据 AI infrastructure 资料索引和我的学习记录，选一个适合我的知识点讲解，等我要求后再测试` | 读取索引、CS 学习记录与相关资料，选择一个符合先修和当前水平的知识点；先讲解并答疑 |
| 从指定方向自动选题 | `CS模式，根据我的学习记录，从 AI infrastructure 的分布式训练方向选一个知识点讲解，等我要求后再测试` | 在指定方向内选题；可把方向换成推理服务、GPU kernel 或集群平台 |
| 复习一本书 | `知识点复习` | 先问复习哪本书，再根据记录选择一个知识点讲解；等你要求后测试 |
| 已经选好书 | `知识点复习，DDIA` | 直接使用明确的书名，不重复询问；也可以说 Distributed Systems |
| 复习既有知识 | `CS模式，复习我之前学过的知识点` | 优先选择到期、薄弱、曾出错或很久未测试的主题 |
| 测试当前内容 | `CS模式，测试我刚学的知识点` | 当前内容明确时，逐题提问，等你作答后再反馈 |
| 总结学习进度 | `CS模式，总结我的学习进度、薄弱点和下一步建议` | 读取 CS 记录，区分已接触、未评估和有证据的掌握 |
| 返回默认状态 | `默认模式` | 清除当前类别与任务模式，恢复按请求目标分流 |

## 2. 在线课程、文档与论文

这些是完整自然语言请求，当前没有单独的短口令。可以复制后替换主题、来源或网址：

- `CS模式，按 AI infrastructure 索引学习 ai.sharding；先讲解 DDP、ZeRO 和 FSDP 的区别，等我要求后再测试。`
- `CS模式，根据我的学习记录，从 AI infrastructure 索引选择一个最适合我的知识点。读取相关官方资料，说明选择理由，先讲解并回答问题，等我要求后测试和记录进度。`
- `CS模式，学习 PyTorch Distributed Overview 中的 DDP，结合一个例子解释梯度同步。`
- `CS模式，学习 PagedAttention 论文，先讲解 KV cache 碎片问题和分页思路，等我要求后再测试。`
- `CS模式，学习这个网址中的知识点：[粘贴网址]。先确认可访问内容，再解释机制和例子，等我要求后再测试。`

实际教学前读取对应资料，不把索引描述当成已阅读全文；无法访问时说明限制，不编造内容或出处。历史不足时说明掌握程度未知，依据先修选择基础切入点，不默认你完全没有基础。

资料入口：[AI infrastructure 资源索引](../study-materials/ai-infrastructure-resources.md)。

## 3. 讲解之后怎么继续？

在当前主题上下文明确时，可以直接说：

| 请求 | 示例 |
|---|---|
| 更直观的解释 | `用一个更简单的例子解释。` |
| 深入机制 | `为什么这样设计？代价是什么？什么情况下会失效？` |
| 定量分析 | `给我一个显存或通信量的计算例子。` |
| 代码实践 | `给我一个最小代码例子，并解释如何验证正确性。` |
| 开始测试 | `测试我。` / `开始测试。` |
| 测试结束并保存 | `结束测试，总结我的掌握程度，并记录学习进度。` |
| 下次继续 | `CS模式，读取我的学习记录，继续上次的 AI infrastructure 学习。` |

测试一次一题，不提前给答案；记录独立作答、提示、错误与下一步建议。只听过讲解不能视为掌握。书籍复习按 [book-review.md](book-review.md) 保存已讲解但未评估的进度；其他学习完成有意义的评估后按 [learning.md](learning.md) 更新记录。保存成功后才报告已记录。

## 4. 准备 AI infrastructure 面试

以下指令会明确进入 interview 类别；这里仅提供快捷入口，具体规则仍由 interview 指令控制。

| 目标 | 可复制指令 |
|---|---|
| 分布式训练模拟 | `面试模式，AI infrastructure，分布式训练方向，围绕训练显存预算进行模拟面试，一次一题。` |
| 推理系统设计 | `面试模式，AI infrastructure，推理方向。让我设计一个满足延迟目标的 LLM serving 系统。` |
| GPU 性能排查 | `面试模式，AI infrastructure，给我一道 GPU 利用率低的排障题，先不要给答案。` |
| 集群平台设计 | `面试模式，AI infrastructure，多租户 GPU 集群调度方向，开始模拟面试。` |
| 根据历史选题 | `面试模式，根据我的 AI infrastructure 面试练习记录，选择一个薄弱主题测试。` |

面试清单：[interview/study-materials/ai-infrastructure.md](../../interview/study-materials/ai-infrastructure.md)。

## 5. 使用规则与记录位置

- 新对话建议使用完整的 `CS模式，……`，避免裸用“学习模式”“复习模式”“测试模式”被默认路由到英语。
- 类别和模式只在当前对话内持续；明确切换类别会清除原任务模式。明确的其他任务请求在该次请求中优先。
- `知识点复习` 是明确的 CS 书籍复习命令；在线资料使用第 2 节的完整请求。它不会因为本速查表而变成在线资料专用口令。
- CS 概念证据保存在 [mastery.md](../mastery.md)，学习过程保存在 [session-log.md](../session-log.md)。
- interview 面试表现保存在该类别的 mastery.md 与 session-log.md；不混写英语、CS 和面试状态。
- 本文件只是指令参考；选题和评价仍需读取最新记录，不能从资源收录推断已掌握。
